# 原始资料契约

所有资料均为本地合成。JSONL一行一条来源观察，row_id仅标识该观察；同业务ID可以在不同revision、批次或接收位置出现。未写revision的静态目录按文件给定值解释，不隐含线上查询。事实字段中的None为缺少来源值，不是零或否。

金额字段以minor结尾时为该币种最小单位整数；数量、位置、时间的单位以字段后缀和政策说明为准。日期为ISO日期；绝对时刻携带偏移；原始received字段决定可见性，不能仅按发生日期提前使用资料。后续业务修改以相同格式输入，不限定样本编号。

## 业务政策

### business_timezone

Asia/Shanghai

### analysis_days

```json
[
  "2026-09-01",
  "2026-09-15",
  "2026-10-01",
  "2026-10-16"
]
```

### data_visible_until

2026-11-01

### quantity

返运不完成需求；只有确认取消数量才减少需求且保留原始数量分母供队列解释。一个line可拆包；转运包的replaces关系继承原数量，不能加总两次。

### promise

revision=2等部分修订只覆盖该数量，余下数量仍用旧日期；原承诺队列永远由revision1日期决定。

### causes

自然日区间[start,end)；先按合同有效交期判断逾期，再按customer > workshop > customs > other优先顺序给每个数量日分配互斥责任；同时保留全部适用原因，不把优先原因称为因果证明。

### contact

每日最多8客户、每客户7自然日最多1次、未获同意不联系；选择比较预期未交付价值与违约风险，必须显示权衡并不重复占客户名额。接受与回执改变后续可联系资格。

### holdout

以received_day不晚于截点为可见事实；交付标签也需可见才算已知。按时间前推评估并保留未完成样本的删失含义。报告固定截点、比较基准、区间覆盖、分组校准与不能支持的外推，不要求预定分数。

### production

production为工坊对lot/line及数量的报工，完成不等于交付；数量以parcel_contents明确映射，生产记录不另外增加需求。后续可报started/completed/rework，按production_id/revision和received_day解释；缺报只表示阶段待核实，不凭物流之外的猜测补齐。

## 资料检查

`python -m unittest discover -s tests -v`只检查资料字节与格式，不是尚未开发业务功能的验收。manifest.json中的摘要对应提交内原始字节，收到后续批次应独立登记来历，不修改旧原始记录。
